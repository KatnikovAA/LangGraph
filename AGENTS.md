# Правила работы с проектом

- Перед изменениями изучать spec.md, фактический код и применимые вложенные инструкции.
- Развивать существующие Workflow, сохраняя совместимость либо версионируя изменения Checkpoints.
- Описывать поведение, конфигурацию, ограничения и проверки в продуктовых руководствах.
- Не добавлять внутренние планы, журналы сессий, временные логи, секреты и локальные БД.
- Использовать нейтральное продуктовое описание в коде, интерфейсе и документации.
- Сохранять обязательные уведомления об авторстве и лицензиях стороннего кода.
- Пользовательский запуск описывать для Live; Demo использовать явно с обозначением синтетических данных.
- Не выполнять платные API calls, остановку серверов, commit/push или Deployment без разрешения пользователя.
- Перед commit проверять diff, автономные тесты и отсутствие секретов; указывать пропущенные проверки.
- Схемы для заметок хранить вне репозитория; продуктовые ресурсы добавлять по согласованному заданию.

## Актуальная документация

При работе с библиотекой, SDK, API, CLI или облачным сервисом использовать Context7:
сначала resolve-library-id, затем query-docs с конкретной темой. Для разных тем
делать отдельные запросы. Рефакторинг, анализ бизнес-логики и редактирование текста
не требуют поиска документации.
