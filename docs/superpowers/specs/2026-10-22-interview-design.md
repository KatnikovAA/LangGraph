# Этап 12 — одно интервью в Web Interface

Дата: 2026-10-22. Дизайн интеграции согласован в чате; пользователь дополнительно
попросил сгруппировать новый код в отдельной папке. Этот документ уточняет границы
реализации и передаётся на проверку перед составлением implementation plan.

## Цель и учебные предпосылки

В существующем браузерном приложении пользователь выбирает «С интервью», вводит
тему и необязательное уточнение, наблюдает два раунда Analyst/Expert, получает
Report и открывает существующий Chat по конкретному завершённому результату.
Academy 1/2/3/4: Chain, State, Conditional Edges, Streaming, Checkpoints,
Research Assistant; предпосылки — этапы 7–11. Реализация не подтверждает практику
и понимание пользователя. Этап 13, Team, Fan-out и Review аналитиков исключены.

интеграцией нового режима; прежний дизайн и пользовательские изменения сохраняются.

## Graph и бюджет

`START → prepare_interview → ask_question → search_sources → answer_question`.
Conditional Edge после ответа возвращает в `ask_question`, если завершён только
один раунд, иначе ведёт в `summarize_interview → save_report → END`.

prepare_interview без модели проверяет тему, уточнение, фиксированную роль и
Workflow. ask_question вызывает Analyst; второй вызов получает первый вопрос
и ответ. search_sources делает один существующий ограниченный поиск на вопрос.
answer_question вызывает Expert только с найденными snippets и допустимыми ID.
summarize_interview одним вызовом создаёт ReportDraft; дополнительной генерации
того же отчёта нет. save_report использует существующие render_report/write_report
и устойчивый идентификатор результата. Обычный успешный путь: 5 model calls,
2 поиска. Никаких скрытых retries; повтор незавершённого внешнего вызова при
Resume учитывается отдельно, exactly-once не обещается.

## State, источники и безопасность

State сохраняет исходную тему, normalized_topic, уточнение, роль, текущий раунд,
вопросы, ответы, запросы поиска, Transcript, реестр источников, ReportDraft,
report_markdown/report_path, Workflow/status и завершённые исполнения шагов.
Список успешных раундов обновляется целиком по номеру, без append-дублирования
при Resume. Серверный Checkpointer сохраняет границы Nodes.

Источники объединяются по точному URL — действующее правило Source.
Порядок реестра определяет стабильные S1/S2/... во всём интервью: второй поиск
дополняет реестр, а не перенумеровывает его. Модель возвращает только source_ids;
ссылки строит код. Ответ проверяет ID относительно доступных ему материалов,
ReportDraft — относительно общего реестра. URL модели не принимаются.
Пустой поиск не останавливает ограниченный Loop: ответ обозначает нехватку данных,
Report отражает ограничения. Expert не заявляет чтение полных страниц.
Тема/уточнение/материалы передаются как данные, отдельно от системных правил.

## Agent Server, BFF, Report и Chat

Добавить server Graph `interview` существующей фабрикой без второго backend.
Thread metadata и Workflow отличают Interview от Research и Chat.
BFF использует текущий SDK, owner checks, журнал идемпотентности и multitask
strategy reject. Reload/reconnect восстанавливают результат принятого запроса,
не повторяют исходный запуск. Resume передаёт None незавершённому Graph.

Адаптер materials принимает завершённый Interview с проверенным Workflow и
возвращает проверенные report_markdown/sources для существующего Chat.
Chat сохраняет pin исходного Thread и точного checkpoint_id; проверка владельца
и завершённости выполняется на backend. Обычный Research сохраняет свой путь
валидации. Report открывается и скачивается действующим маршрутом.
Memory и существующие Assistants сохраняют поведение.

## События и восстановление

Использовать поддерживаемый установленными версиями get_stream_writer/custom
или tasks с updates/messages. Зафиксированные версии: LangGraph 1.2.16,
Agent Server 0.16.2, SDK 0.4.8. Новейшие примеры документации не считать
доказательством совместимости — проверить фактический API и HTTP.

Публичный контракт: run_id, node, round, execution_id, status, label, timestamp.
running отправляется до работы Node, done после успеха, error при исключении;
разные раунды и повторные попытки имеют разные execution_id. BFF фильтрует поля
и добавляет авторитетный run_id. Длительность выводится из реальных timestamps.
Нет процентов готовности, hidden reasoning, полного State и конфигурации.
Сохранённый State/история восстанавливают завершённые шаги и pending Node;
активный Run проверяется сервером, разрыв SSE не оставляет вечный running.
Ошибки не маскируются транспортным done.

Provider chunks показывать только при подтверждённой поддержке с отдельным ID
вызова, ролью, раундом и отметкой предварительного текста. Без chunks работают
Progress Events и готовые валидированные сообщения; Demo не имитирует provider
token streaming нарезкой готового текста.

## UI

Режимы «Обычное / С интервью» в текущей форме. В интервью видны уточнение,
фиксированная роль аналитика и лимит «2 раунда». Основная область содержит
Transcript по раундам, раскрываемые title/URL/snippet и итоговый Report.
Рядом — «Ход выполнения»: схема Nodes со стрелками, человеческие подписи,
технические имена вторично, активный шаг/раунд, done/pending/error и Resume.
На узком экране панель располагается последовательно с содержимым.
Сохраняются синяя sidebar, светлый canvas, типографика, отступы и компоненты.
Отдельные подписи Analyst/Expert, keyboard/focus, aria-live, перенос длинных
строк, empty/loading/running/error/completed; сырой JSON не заменяет Transcript.

## Проверки и эксплуатация

Fake model/search: два раунда, зависимость второго вопроса от первого ответа,
бюджеты, пустой поиск, malformed output, чужие source_ids, стабильность ID,
точное объединение URL, ошибка второго ответа и Resume, повтор save_report,
адаптер Chat и pin, owner isolation, идемпотентность и старые Research/Chat/Memory.

HTTP и браузер: форма, running во время медленного Node, шаг/раунд, Transcript,
источники, reload/reconnect без нового Run, ошибка/Resume, скачивание, Chat,
широкий/узкий viewport, длинные строки, клавиатура и отсутствие overflow.
Скриншот не равен browser E2E. Недоступные проверки явно записываются.

Отдельная Demo-среда на проверенных свободных портах с отдельным data-root;
существующие Live и Demo серверы не останавливать и не перенастраивать.
Demo проходит тот же Graph, источники явно помечены, второй вопрос использует
первый ответ. Live использует текущие Polza/Tavily, платные вызовы запрещены
без отдельного разрешения. Tracing выключен. Новые пакеты не планируются.
