# Research Assistant — продуктовая спецификация

## Назначение

Локальное приложение для исследования технических тем, подготовки Markdown-отчётов
с источниками и обсуждения результатов. Доступны Web Interface и CLI.
Публичная документация описывает продукт и воспроизводимый запуск.

## Research Workflow

- Нормализовать тему, отклонять пустой ввод до вызова провайдера.
- Генерировать структурированный план через Pydantic / JSON Schema.
- Review позволяет утвердить, заменить план или отменить запуск.
- По утверждённому плану искать источники с ограниченной параллельностью.
- Объединять точные дубли URL с сохранением принадлежности к разделам.
- Проверять ID источников в ReportDraft и программно формировать ссылки.
- Сохранять Markdown атомарно; completed означает успешную запись результата.

## Interview и Team

- Interview: два раунда Analyst/Expert, поиск по вопросам и итоговый синтез.
- Общий Interview Core используется отдельным Graph и Workers команды.
- Team: две редактируемые роли, Review до внешних вызовов, параллельные интервью
  и общий Report после сбора обоих результатов.
- Сохранять Transcript, provenance источников, ограничения и Progress Events.

## Chat и память

- Диалог привязан к точному завершённому Research Checkpoint.
- Parent Graph хранит полную историю и Summary; Agent Subgraph обрабатывает вопрос.
- Tools используют сохранённые материалы; память проверяет owner.
- Profile и Notes доступны между диалогами одного пользователя.
- Запись памяти требует явного намерения и подтверждённого результата Tool.
- Контекст ограничивается целыми блоками; оценка токенов приблизительная.

## Persistence и Web

- CLI использует SqliteSaver; Agent Server управляет собственной Persistence.
- Серверные данные и CLI Checkpoints разделены; несовместимые данные не удаляются.
- Resume продолжает работу; Replay/Fork создают варианты с отдельными артефактами.
- BFF связывает request_id с Run и восстанавливает неподтверждённые запросы.
- Streaming передаёт безопасные события; итоговый результат сохраняется отдельно.
- Live и Demo имеют раздельные data roots. Секреты остаются на сервере.

## Публикация и качество

- README представляет возможности, архитектуру, запуск и фактические ограничения.
- В публикуемом дереве нет внутренних планов и журналов сессий.
- Уведомления сторонних правообладателей сохраняются.
- Автономные тесты не вызывают платные API; HTTP/restart/checkout opt-in.
- Аутентификация, публичный Deployment и exactly-once не заявляются.
- Качество провайдеров оценивается отдельно от автономных проверок.
