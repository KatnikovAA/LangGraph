# Research Assistant — спецификация и состояние реализации

## Назначение

Python-приложение принимает техническую тему, составляет план исследования,
находит источники и формирует Markdown-отчёт. Возможности добавляются постепенно;
каждый завершённый этап должен давать проверяемый результат.

## Текущее состояние

### Этап 9 — Breakpoints, Editing State и Time Travel

Статус: завершён; автономно проверен. Academy 3: Breakpoints, Editing State and Human Feedback,
Dynamic Breakpoints, Time Travel. Предпосылки: Checkpoints, Thread ID, interrupt,
Resume. History/Inspection только читают; статический interrupt_before перед
prepare_search сохраняется в Workflow. Replay/Fork — native update_state от
Checkpoint после generate_plan перед review_plan, без выполнения API при создании.
Каждая альтернатива получает artifact_id и отдельный Report. Chat привязывается
к завершённому Research checkpoint_id; прежние Chat без такой привязки требуют
создать новый диалог, данные не удаляются. Research version=2 сохраняется.
Реализация не подтверждает понимание пользователя. Без Store/LTM/Deployment/API.
Chat version=3: привязка к Research checkpoint_id, а не к latest. CLI:
--history/--inspect, --replay/--fork с --checkpoint-id, --plan-file для Fork,
--resume THREAD --checkpoint-id BRANCH_CHECKPOINT; --research-checkpoint-id
для нового --discuss. Подготовка ветки отделена от выполнения. Report пути
зависят от artifact_id; Resume сохраняет идентификатор, включая ошибку записи.
Static флаг --break-before-search сохраняется; dynamic Review по-прежнему
Command(resume=...), static/error продолжение через None. Исходные данные не удаляются.

Проверка этапа 8: 104 автономных теста, OK; подробности в журнале ниже.

### Этап 8 — Context Management, Subgraphs и Streaming

Статус: завершён; автономно проверен. Актуальная нумерация: Report + Persistence — 5,
Parallelization — 6, обсуждение отчёта — 7. Parent Chat Graph хранит полную
историю, Summary и границу по ID; compiled Agent Subgraph обрабатывает один
вопрос. Контекст ограничивается целыми блоками реплик, включая Tool Messages.
Бюджеты приблизительные, включают правила, Report, Sources/Tools и резерв ответа.
Summary обновляется только по порогу, атомарно с границей. Chat version=2:
старые Chat Threads отклоняются без удаления; Research version=2 не меняется.
--stream использует updates/messages с Namespace, stderr для прогресса и
предварительного текста, один финальный JSON в stdout. Без платных API.
Academy: модуль 2 — Filter/Trim/Summarization/External Memory; модуль 3 —
Streaming; модуль 4 — Subgraphs. Предпосылки: MessagesState, Tool Calling,
Agent Loop, Checkpointer. Практика и понимание пользователя не подтверждены.

Бюджеты новых Chat: context-budget=8192, answer-reserve=512,
summary-threshold=1600, summary-budget=512, recent-turns=2; сохранены в State.
Оценка: JSON-символы / 3 + надбавка, не tokenizer провайдера. Проверяются
Report/правила/Sources/Tool schema/Summary/история/текущий вопрос/Tool results
и резерв ответа; текущий блок не обрезается. Порог проверяет ещё не пересказанные
завершённые реплики; Summarizer получает прежнее Summary и только новый префикс.
Последние recent-turns не пересказываются, но Trim может исключить старые
завершённые блоки из входа при недостатке бюджета. Полная история остаётся.
Один вызов Summarizer по порогу — дополнительно к лимиту 3 вызовов Agent.
Ошибка или превышение размера Summary не меняют Summary/границу. После ошибки
возобновление через --chat ID [--stream], без --question. Per-invocation Subgraph
наследует Checkpointer через compile() без собственного Thread; успешные шаги
проверены при Resume, в том числе из нового процесса. Chat v1 отклоняется с
--discuss по прежнему Research ID, включая незавершённую старую топологию.
Обычные Research-команды, Plan schema и API-параметры не менялись.

### Этап 7 — обсуждение отчёта: Chain, Agent и Agent with Memory

Статус: завершён; автономно проверен. Результат этапа 7 (далее расширен этапом 8):
отдельный Chat Graph. Новый Chat Thread связан
с completed Research Thread версии 2, но не переиспользует его ID/State.
На этапе 7: Chat version=1/mode=report_chat; этап 8 повышает Chat до версии 2.
Research version=2 остаётся неизменной.
Multiple Schemas: вопрос на входе, MessagesState и материалы внутри, ответ/статус
на выходе. Runtime-валидация обязательна. SystemMessage/Report добавляются только
в контекст модели, в истории сохраняются новые Human/AI/Tool Messages.
Ручной Agent Loop через StateGraph, bind_tools и настоящий ToolNode get_source:
только сохранённые title/URL/snippet связанного исследования, стабильные S1/S2,
без сети и чтения полных страниц. Router проверяет tool_calls.
На вопрос максимум 3 вызова модели и 3 выполнения Tools; остановка закрывает
все Tool Calls через ToolMessage и добавляет итоговое объяснение.
CLI: --discuss RESEARCH_ID --question TEXT создаёт Chat; --chat CHAT_ID
--question TEXT продолжает. --chat CHAT_ID без вопроса возобновляет незавершённый
вопрос после ошибки, без дублирования HumanMessage. История хранится в SQLite.
Ошибки ожидаемых вызовов модели санитизируются; платные запросы не выполняются.
Academy 1: Chain/Router/Agent/Agent with Memory; Academy 2: State Schema/Multiple
Schemas. Наличие кода не подтверждает изучение. Без этапов 8–11 и новых пакетов.

### Этап 6 — Parallelization + Reducers + Map-Reduce

Статус: завершён; автономно проверен. Утверждённый Plan → prepare_search (проверка всех запросов)
→ Send по одному search_section на раздел → collect_sources → Report либо END.
Worker Input содержит section_index/query; каждый Worker возвращает одну batch.
search_batches объединяются через Annotated[list[SearchBatch], operator.add].
Fan-in проверяет полноту и уникальность batches, сортирует по section_index,
дедуплицирует точные URL с прежним порядком и section_indexes. Пустой Plan
идёт прямо в collect_sources. Cancel не запускает поиск. Один поиск на Thread,
сброс add-Reducer через [] не используется. CLI max_concurrency=2 на верхнем
уровне RunnableConfig. Workflow версии 2 несовместим с прежними Checkpoints;
БД не удаляется. Resume использует Pending Writes успешных Tasks, failed Task
может повториться; exactly-once не гарантируется. API без разрешения не вызываются.
Компактность и прежние режимы/Report/Persistence сохраняются. Новых пакетов нет.
Academy: State Reducers (2), Parallelization и Map-reduce (4), практика пользователя
ещё не подтверждена. Subgraphs, Agent, Streaming и Long-Term Memory не закрываются.

### Этап 5 — Report Generation + Persistence

Статус: завершён; автономно проверен. Реализация в двух блоках: A — ReportDraft, проверка ID
источников, программный Markdown и атомарная запись; B — файловый SqliteSaver,
Pause и Resume между процессами. Полный режим требует review/search/report;
прежние режимы сохраняются. В State сохраняются версия Workflow, режим,
абсолютные пути БД и output-dir, thread_id; секреты и клиенты не сохраняются.
Resume проверяет get_state, версию и режим, продолжает interrupt через Command,
ошибку через invoke(None), завершённый Thread возвращает без повторного запуска.
Checkpoints синхронные. report_ready предшествует записи, completed — только
после атомарной замены файла. Cancel/no_sources завершаются без Report.
Промпт плана 1 раздел/1 вопрос/40 слов, Tavily max_results=1, snippet<=500
сохраняются; ручные планы не ограничены числом разделов.
Проверки автономные, включая два subprocess и ошибку записи с восстановлением.
API без отдельного разрешения не вызываются. Exactly-once не гарантируется:
в версии 1 незавершённый Node search_sources мог повторить весь цикл запросов.
В версии 2 поиск разделён на Tasks, успешные Pending Writes используются при Resume.
Academy: Research Assistant, Persistence / External Memory, Human-in-the-Loop;
предпосылки — State, Nodes, Conditional Edges, interrupt. Наличие реализации
не подтверждает изучение; Store, Long-Term Memory, Time Travel, Parallelization,
Subgraphs и Deployment не считаются пройденными.

## Этап 1 — приём темы и подготовка заявки

Статус: завершён.

### Поведение

CLI принимает обязательный аргумент `--topic`. Сохраняет исходную строку,
сворачивает последовательности пробельных символов в один пробел и удаляет
пробелы по краям. Для корректной темы выводит читаемый JSON в stdout.
Пустая после нормализации тема вызывает понятное сообщение в stderr и ненулевой
код завершения без traceback ожидаемой ошибки.

### Граф и данные

`START → validate_topic → prepare_request → END`

- `topic: str` — обязательный исходный ввод.
- `normalized_topic: str` — появляется после проверки.
- `status: Literal["ready"]` — появляется после подготовки заявки.
- `ready` означает готовность к планированию, а не завершение исследования.
- Схема состояния: `TypedDict`; выходные поля при вводе могут отсутствовать.
- `validate_topic` возвращает обновление `normalized_topic`, при пустой теме
  поднимает `ValueError`.
- `prepare_request` возвращает обновление `status`.
- Узлы не изменяют входной словарь на месте.
- Построение графа отделено от CLI; используются `StateGraph`, `compile()`, `invoke()`.
- CLI обрабатывает ожидаемую ошибку проверки, не скрывая неожиданные ошибки.

### Границы

Без модели, API-ключей, поиска, памяти, checkpointer, streaming, условных переходов,
подграфов, веб-интерфейса и требования Studio.

- [x] Исходное значение `topic` сохраняется.
- [x] Пустая и пробельная тема отклоняются.

- Модель Польза AI пишет краткий обзор только по сохранённым snippets и плану,

- Идентификаторы источников проверять в коде; Markdown References формировать

- Сохранить текущие настройки компактности плана/Tavily и отсутствие жёсткого
  лимита выходных токенов. Отчёт требует одного дополнительного LLM-вызова.
- State: report_markdown, report_path; completed только после успешной записи.
- Файл UTF-8, детерминированное безопасное имя по thread_id, атомарная замена
  и Idempotency при повторной записи; запись отдельно от LLM Node.

### Persistence

- В report-режиме использовать файловый `SqliteSaver`, пакет
  `langgraph-checkpoint-sqlite`, контекстный менеджер на весь цикл выполнения.
- Новые опции: `--resume THREAD_ID`, `--checkpoint-db PATH`, `--output-dir PATH`,
  `--pause-after-plan` (сохранить Pause и завершить CLI без отмены).
- Дефолты: `.research_assistant/checkpoints.sqlite` и `reports/`.
- `--resume` использует прежний thread_id, тот же файл БД и совместимый Graph;
  новая тема и переключение режима сохранённого Thread не допускаются.
- Хранить несекретные параметры режима и абсолютные пути для корректного Resume.
  Ключи API в State/Checkpoint не сохранять. Новый запуск получает новый ID.
- Перед Resume вызвать get_state: Pause → Command(resume=decision),
  ошибка незавершённого Node → invoke(None, config), завершённый Thread →
  вернуть сохранённый результат без повторных внешних вызовов.
- Применять синхронное сохранение Checkpoints, если доступно в установленной версии.
- Не обещать exactly-once API calls: незавершённый Node может повториться.
  Поиск внутри одного Node при сбое может повторить запросы разделов.
- БД, её служебные файлы и reports исключить из Git.

### Приёмка
